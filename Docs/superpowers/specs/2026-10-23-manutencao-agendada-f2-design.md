# Manutenção agendada — F2 (integração, edição e prorrogação) — design

Data: 2026-10-23 · Branch: `feat/manutencao-agendada` (sobre a F1, 6722692) · Desenho aprovado em chat com dois ajustes.

Fundo e porquês: `Docs/manutencao-agendada-architecture/` (MA01–MA18; esta fatia acrescenta MA19–MA26).
Este documento fixa **o que a F2 entrega e como se prova**.

## Decisões aprovadas

| # | Decisão |
|---|---|
| MA19 | Agendar a partir de Equipamentos: item no menu da linha **e** no drawer; sem seleção múltipla na tabela (a checklist do modal é a seleção múltipla, por unidade). No Mapa o item não aparece (`acoesDeGestao=false`, M06) |
| MA20 | Agendar a partir da Unidade: o botão já existente do cabeçalho abre o modal com a unidade travada; escopo padrão continua "Equipamentos selecionados" (MA18); nunca pré-marcar todos como substituto de "Unidade inteira"; dica quando o operador marca todos. Banner de janelas vigentes no detalhe da unidade |
| MA21 | Editar: AGENDADA permite tudo (unidade, escopo, equipamentos, início, fim, motivo); ATIVA só o fim; CONCLUÍDA/CANCELADA/EXPIRADA nada. Trocar a unidade limpa a seleção no formulário e o backend recusa ids que não pertençam à unidade nova; equipamento **já vinculado** que ficou inativo ou mudou de unidade sozinho continua na janela se a unidade da janela não mudou |
| MA22 | Prorrogar e antecipar são a mesma operação, "Alterar fim", só em ATIVA. Janela CONCLUÍDA não reabre: a tela oferece "Agendar continuação" e diz que os equipamentos são pingados por alguns segundos no intervalo |
| MA23 | Teto de duração (72 h, `MANUTENCAO_AGENDADA_DURACAO_MAXIMA`) vale para o total da janela, de `inicio_previsto` até o novo fim, checado também no WHERE do CAS |
| MA24 | Registro de alterações em tabela própria com JSONB `antes`/`depois`, autor e instante; a tela mostra só a última |
| MA25 | Agendador desligado: **Alterar fim** recusado (409, mensagem do MA16); **Editar AGENDADA permitido**, sem tentativa de ativação imediata. AGENDADA vencida (início já passou, agendador desligado) só se edita movendo o início para o futuro: a validação é a mesma da criação |
| MA26 | Concorrência de edição por `versao` (CAS); janela de unidade × equipamento criado durante a conclusão é **convergência em até uma passada**, não CAS, declarado no teste e aqui |

## Critério de sucesso

1. Operador agenda a partir da linha, do drawer e da unidade, com unidade travada e equipamento pré-marcado; no Mapa não há o item.
2. Edita uma AGENDADA (inclusive com o agendador desligado), altera o fim de uma ATIVA (prorroga ou antecipa), e a lista mostra "editada por X às HH:MM".
3. Prorrogar uma janela que acabou de concluir responde 409 e a tela oferece "Agendar continuação" pré-preenchido.
4. As quatro corridas (§4) passam com duas threads, barreira, 30 repetições, distribuição impressa, zero ilegítimo, e cada uma fica vermelha sem a guarda (saída registrada).
5. Suítes completas (front; back com Docker, contagem completa), e2e Playwright por clique com capturas de cada fluxo, exercício no banco da carga com equipamento real (nunca o Servidor AD Core), conferido por SQL.

## 1. Banco — `V22__add_versao_e_alteracoes_manutencao_agendada.sql`

```sql
ALTER TABLE manutencao_agendada ADD COLUMN versao INTEGER NOT NULL DEFAULT 0;

CREATE TABLE manutencao_agendada_alteracao (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    manutencao_id BIGINT NOT NULL REFERENCES manutencao_agendada(id) ON DELETE RESTRICT,
    tipo VARCHAR(12) NOT NULL,
    alterado_por_id BIGINT NOT NULL REFERENCES usuarios(id) ON DELETE RESTRICT,
    alterado_em TIMESTAMPTZ NOT NULL,
    antes JSONB NOT NULL,
    depois JSONB NOT NULL,
    CONSTRAINT ck_manutencao_alteracao_tipo CHECK (tipo IN ('EDICAO', 'PRORROGACAO', 'ANTECIPACAO'))
);
CREATE INDEX ix_manutencao_alteracao_janela ON manutencao_agendada_alteracao (manutencao_id, alterado_em DESC, id DESC);
```

`versao` incrementa em **toda** escrita na linha (os CAS da F1 em `CoberturaManutencao` passam a fazer
`versao = versao + 1`; nenhum muda de condição). Retrato `antes`/`depois`: `unidadeId`, `escopo`,
`equipamentoIds` (ordenados), `inicioPrevisto`, `fimPrevisto`, `motivo`.

## 2. Backend

### 2.1 API

| Método | Rota | Papel | Corpo / resposta |
|---|---|---|---|
| GET | `/manutencoes?situacao&busca&unidadeId&page&size` | 3 papéis | `unidadeId` opcional estreita a lista; nada fica visível que a lista sem filtro já não mostre (não há permissão por unidade no modelo) |
| GET | `/manutencoes/{id}` | 3 papéis | `ManutencaoResponse` atual (edição carrega valores e `versao` frescos; a continuação consulta a situação) |
| PUT | `/manutencoes/{id}` | ADMIN, OPERADOR | `EditarManutencaoRequest` = campos de criação + `versao` (objeto completo, sem PATCH parcial) |
| PATCH | `/manutencoes/{id}/fim` | ADMIN, OPERADOR | `AlterarFimRequest { fimPrevisto, versao }` |

`SecurityConfiguration`: acrescentar `/api/v1/manutencoes/**` à lista de **PUT** (hoje cairia em
ADMIN-only em silêncio). PATCH e GET já cobrem.

`ManutencaoResponse` ganha `versao` e `ultimaAlteracao: { tipo, por: Referencia, em } | null` (uma consulta
por página, `DISTINCT ON (manutencao_id)`, sem N+1).

### 2.2 Editar AGENDADA (`ManutencaoAgendadaService.editar`)

Numa transação:
1. `SELECT … FROM manutencao_agendada WHERE id = :id AND status = 'AGENDADA' AND versao = :versao FOR UPDATE`
   (+ ids da tabela de ligação). Vazio → 404 se não existe; 409 "Nao e possivel editar: a janela esta ATIVA.
   Use Alterar fim." / "…esta CONCLUIDA." etc.; 409 "A janela foi alterada por outra pessoa. Recarregue e tente de novo."
   se só a versão divergiu.
2. Validar como na criação (unidade ativa, motivo, fim > início, início ≥ agora − 5 min, duração ≤ máximo). Equipamentos:
   se a unidade **não** mudou, ids já vinculados passam sem checar ativo/unidade; ids novos exigem ativo e da unidade.
   Se a unidade mudou, todos são novos.
3. `UPDATE … SET …, versao = versao + 1, updated_at = :agora WHERE id = :id AND status = 'AGENDADA' AND versao = :versao`
   (segunda guarda; 0 linhas = `IllegalStateException`, impossível sob o lock).
4. Trocar a ligação (`DELETE` + `INSERT`), inserir a alteração `EDICAO`.

Depois do commit, **só com o agendador ligado**: `ativarSeDevida` e, se ativou, `reavaliarCobertos`, com a
mesma tolerância a falha do MA18 (WARN, 200 com a janela).

### 2.3 Alterar fim de ATIVA (`alterarFim`)

Recusa com 409 `MSG_DESLIGADO` se o agendador está desligado. Numa transação:
1. `SELECT … WHERE id = :id AND status = 'ATIVA' AND versao = :versao FOR UPDATE`. Vazio → 404/409 como acima
   (CONCLUIDA: "Nao e possivel alterar o fim: a janela esta CONCLUIDA. Agende uma continuacao."; a hora de conclusao a tela formata no fuso dela, a partir de `GET /{id}`).
2. `novoFim > agora` (senão 400 "Para terminar agora use Encerrar agora"); `novoFim ≠ fimAtual` (400);
   `novoFim − inicio_previsto ≤ máximo` (400 "A janela nao pode passar de N horas desde o inicio").
3. `UPDATE … SET fim_previsto = :novoFim, versao = versao + 1 WHERE id = :id AND status = 'ATIVA' AND versao = :versao
   AND :novoFim > :agora AND fim_previsto_maximo_ok` (teto no WHERE: `inicio_previsto + :maximaSegundos * interval '1 second' >= :novoFim`).
4. Alteração `PRORROGACAO` (novo > antigo) ou `ANTECIPACAO`.

Nada a reavaliar: a janela continua ATIVA; se antecipou para daqui a pouco, o reconciliador a conclui.
O reconciliador concluindo no mesmo instante disputa o mesmo lock de linha: o Postgres reavalia o WHERE dele
contra a versão commitada (fim novo ⇒ não conclui).

### 2.4 O que não muda

Escopo UNIDADE dinâmico (MA05), reconciliador, `reavaliar`, cancelar/encerrar (só ganham `versao + 1`).

## 3. Frontend

- **`app-agendar-manutencao`** ganha dois inputs, sem componente novo:
  - `preset: { unidadeId, travarUnidade, equipamentoIds?, escopo?, motivo?, inicio?, fim? } | null` — pré-preenche.
  - `janela: ManutencaoResponse | null` — modo edição: título "Editar janela #N", botão "Salvar alterações",
    `PUT` com `versao`; valores carregados de `GET /{id}` ao abrir. Checklist mostra ativos da unidade **mais**
    os já vinculados com nota ("inativo", "agora em outra unidade"); trocar a unidade limpa a seleção (já é assim).
  - Dica quando todos os ativos estão marcados: "Todos marcados. Para incluir também os equipamentos criados durante a janela, use Unidade inteira."
  - Criação continua exigindo agendador ligado; edição não.
- **`app-alterar-fim`** (novo, `app-modal`): campo fim (`datetime-local`), fim atual, limite "até DD/MM HH:MM ({N} h desde o início)".
  Em 409, consulta `GET /{id}`; se CONCLUIDA, troca o conteúdo para "A janela #N concluiu às HH:MM. Os equipamentos voltaram
  a ser verificados: até a nova janela ativar, eles são pingados por alguns segundos." com **Agendar continuação**, que emite
  um preset (mesma unidade/escopo/equipamentos/motivo, início agora, fim pedido).
- **Lista `/manutencoes`**: AGENDADA → Editar, Cancelar; ATIVA → Alterar fim (desabilitado com agendador desligado), Encerrar agora.
  Abaixo de "Criado por": "editada por X às HH:MM" quando há `ultimaAlteracao`.
- **Equipamentos**: item "Agendar manutenção" no menu da linha (desabilitado sem permissão, equipamento inativo ou agendador
  desligado) e botão no rodapé do drawer sob `acoesDeGestao() && canManageInventory()`; foco volta à gaveta pelo padrão
  existente (`guardarGatilhoDaGaveta`/`devolverFocoAGaveta`).
- **Unidade**: o botão desabilitado de `unidade-detalhe.component.html:44` passa a abrir o modal com a unidade travada
  (desabilitado sem permissão, unidade inativa ou agendador desligado, com `title` explicando). Banner acima dos KPIs:
  janela ATIVA ("Janela #41 ativa até 12:00 · motivo") e próxima AGENDADA, link para `/manutencoes`; falha da chamada
  esconde o banner sem derrubar a tela.
- Componentes compartilhados (`app-modal`, `ConfirmDialog`, `StatusBadgeComponent`, `.tabela`, `app-paginacao`); Escape fecha,
  foco entra ao abrir e volta ao gatilho.

## 4. Corridas (Postgres real, `@RequerDocker`, `CyclicBarrier`, `@RepeatedTest(30)`)

| # | Corrida | Desfechos legítimos | Ilegítimo | Reversão (remover → vermelho) |
|---|---|---|---|---|
| C1 | Editar AGENDADA (troca A→B, mantém início devido) × `reconciliar` | edição ganha → ATIVA com B, B em manutenção, A fora; job ganha → 409, ATIVA com A, A em manutenção | ATIVA com B na ligação e A em manutenção / B fora | `status = 'AGENDADA'` do SELECT e do UPDATE **e** o `versao = versao + 1` da ativação (`ativarDevidas`/`ativarSeDevida`). Guarda dupla: remover só um dos dois segue verde (ver `Docs/validacao-producao/manutencao-agendada-f2.md`) |
| C2 | Alterar fim (+1 h) × `reconciliar` com fim vencido | prorrogou → ATIVA, fim novo, equipamento dentro; concluiu → 409, CONCLUIDA, fim antigo, equipamento fora | CONCLUIDA com fim alterado; ATIVA com equipamento fora | `status = 'ATIVA'` do SELECT e do UPDATE **e** o `versao = versao + 1` da conclusão (`concluirVencidas`). Guarda dupla: remover só um dos dois segue verde (ver `Docs/validacao-producao/manutencao-agendada-f2.md`) |
| C3 | Duas edições com a mesma `versao` (variantes editar×editar e fim×fim) | exatamente um 200 e um 409; estado final inteiro de um pedido; uma linha de alteração | dois 200, campos misturados, união de equipamentos, duas alterações | `versao = :versao` do SELECT e do UPDATE |
| C4 | Janela UNIDADE concluindo × equipamento criado na unidade | após no máximo **uma** passada extra, nenhum divergente; distribuição de quantos precisaram dela | divergente depois da passada extra | `divergentes()` da passada |

C4 **não é CAS**: criação e conclusão não dividem lock; a garantia é o reconciliador de nível. Declarado no
Javadoc do teste e na evidência. Sem corrida, testados também: equipamento movido para fora sai na hora;
equipamento excluído durante ATIVA de unidade não quebra a conclusão; os dois casos do MA21 (unidade trocada
recusa id antigo; equipamento que mudou sozinho continua).
