A04.1 — Homologação Integrada de Usuários e RBAC — Infra Monitor

1. Objetivo

Homologar de ponta a ponta a implementação da A04, conectando o frontend Angular ao backend autenticado correto da A02/A02.1 e executando cenários reais de administração de Usuários e RBAC.

Esta fase não deve criar novas funcionalidades.

Ela deve fechar as duas ressalvas deixadas pela A04:

homologação manual não executada contra backend com /auth/login e /auth/me;

cobertura automatizada de rotas/sidebar/componentes/RBAC ainda inferior ao solicitado.

Ao final, a A04 deve estar efetivamente homologada ou reprovada com bug concreto.

PARTE A — GARANTIR BACKEND CORRETO

4. Identificar processo backend

Antes de qualquer homologação:

verificar processos Java ativos;

confirmar qual processo responde em localhost:8080;

parar backend antigo/desatualizado se necessário;

não assumir que health=200 significa versão correta.

5. Confirmar rotas de autenticação

Com backend candidato ativo, testar:

POST /api/v1/auth/login
GET /api/v1/auth/me

O endpoint /auth/me sem token deve retornar algo equivalente a:

401 UNAUTHORIZED

e não:

404

Se retornar 404:

backend incorreto

Não prosseguir até iniciar o JAR/código certo.

6. Build backend correto

No backend atual:

.\mvnw.cmd clean package

ou comando real equivalente.

Resultado obrigatório:

BUILD SUCCESS

7. Banco isolado

Subir PostgreSQL isolado de teste/homologação.

Usar banco limpo ou dedicado, por exemplo:

inframonitor_a041

Não usar produção.

8. Configuração auth backend

Definir no processo somente:

JWT_SECRET
JWT_ISSUER
JWT_ACCESS_TOKEN_MINUTES
BOOTSTRAP_ADMIN_ENABLED
BOOTSTRAP_ADMIN_NAME
BOOTSTRAP_ADMIN_EMAIL
BOOTSTRAP_ADMIN_PASSWORD

Sem expor valores no relatório.

9. Startup

Iniciar backend correto.

Confirmar:

GET /actuator/health
→ 200

Depois:

POST /api/v1/auth/login

com ADMIN de homologação.

Esperado:

200
