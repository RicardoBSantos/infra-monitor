PARTE A — HARDENING DO RBAC VISUAL

5. Remover autorização visual por CSS genérico

Auditar implementação semelhante a:

.shell--readonly ...

que esconde genericamente botões baseado em seletores CSS.

Esse padrão não deve ser a estratégia principal de RBAC visual.

Remover/substituir se estiver sendo usado para autorização.

CSS pode controlar aparência, mas não deve decidir semanticamente quais ações existem.

6. Autorização explícita

Cada feature com ação mutável deve consultar regra explícita.

Pode utilizar:

AuthStateService
AuthorizationService/helper
computed

Exemplos conceituais:

canManageInventory()
canCloseIncident()
canManageUsers()

Não criar engine genérico de permissions.

7. Helpers recomendados

Pode existir service/helper simples:

AuthorizationService

ou métodos no AuthState, desde que responsabilidades fiquem claras.

Exemplos:

canRead()
canManageInventory()
canManageMonitors()
canCloseIncident()
isAdmin()

Os nomes devem refletir RBAC da A01.
