R04.5 --- Integração Frontend do PDF e Homologação Final das Exportações

Objetivo

Integrar no Angular o PDF server-side da Visão Geral homologado na R04.4
e executar a homologação integrada final da camada de exportações.

Considere homologadas R04.1, R04.2, R04.3 e R04.4. Não redesenhe
contratos homologados sem bug real reproduzido.

Antes de alterar:

git status
git diff

Preserve alterações preexistentes que não pertençam à R04.5.

Ambiente obrigatório

Antes de smoke/browser/homologação, obrigatoriamente disponibilize:

Backend atualizado: http://localhost:8080

Frontend atualizado: http://127.0.0.1:4200

PostgreSQL 16 isolado

Procedimento: verificar portas e processos antigos; encerrá-los quando
necessário; subir PostgreSQL; subir backend atualizado e aguardar
/actuator/health = 200; subir frontend atualizado e aguardar HTTP 200;
somente então iniciar Chrome/Playwright. Não marcar
ambiente/browser/smoke como pendente sem tentar subir os serviços.

Contrato PDF

Usar exatamente:

GET /api/v1/relatorios/visao-geral/export/pdf

Parâmetros: inicio, fim. Máximo de 31 dias. Não enviar page,
size ou sort artificial.

Frontend

Adicionar método tipado no RelatorioApiService com
responseType: 'blob', observe: 'response' e HttpResponse<Blob>.
Preservar o Blob; não converter/reconstruir PDF no Angular.

Adicionar botão Exportar PDF somente na Visão Geral. As seis áreas
analíticas continuam exclusivamente com Exportar CSV.

O PDF deve usar exatamente o período atual da Visão Geral, sem
truncamento silencioso. Se o período for inválido e o frontend puder
detectá-lo, não enviar request inválida.

Download seguro

Fluxo:
HttpResponse<Blob> → Blob → URL.createObjectURL() → <a download> → cleanup → URL.revokeObjectURL().

Ler Content-Disposition, suportar filename e filename*, preferindo
filename* válido. Sanitizar path traversal, separadores, controles e
nomes inválidos. Fallback: visao-geral_<inicio>_<fim>.pdf. Extensão
final obrigatória .pdf.

Validar Content-Type: application/pdf. Blob JSON de erro nunca deve
ser salvo como PDF.

Implementar idle/loading/error; durante download, botão disabled. Duplo
clique deve gerar uma request e um download. Sucesso/erro restaura
estado. Exportar não pode limpar período, trocar aba, resetar
widgets/filtros ou disparar requests duplicadas.

Erros e RBAC

Homologar 400, 401, 403, PASSWORD_CHANGE_REQUIRED e 500. Erros devem
produzir mensagens seguras, nunca arquivo, nunca stack trace. JSON
ErroResposta em Blob pode ser decodificado somente para tratamento de
erro.

Executar login/logout real pela UI para ADMIN, OPERADOR e VISUALIZADOR.
Para cada papel: Relatórios e Visão Geral acessíveis, botão visível,
request autenticada, 200, download e PDF válido, sem /forbidden.
Validar também sem JWT=401, conta inativa=401 e
PASSWORD_CHANGE_REQUIRED=403.

Browser, Network e requests

No Chrome/Playwright verificar GET, Bearer via interceptor, inicio/fim,
ausência de page/size, Content-Type, Content-Disposition, status e CORS.
Não registrar token. Confirmar uma interação → uma request em duas
execuções limpas.

PDF real

Analisar o arquivo realmente baixado pelo navegador. Validar extensão
.pdf, assinatura %PDF, tamanho > 0, filename seguro, estrutura e
parsing. Preferir PDFBox/parser equivalente; não usar OCR como teste
principal.

Validar conteúdo: Infra Monitor, Visão Geral, período, geração, três
KPIs, ranking de Unidades, ranking de Equipamentos e Latência por
Monitor. Com massa controlada, validar CALCULADO, SEM_DADOS,
SEM_MONITORAMENTO, PRECISA, INFERIDA e NULLS LAST quando aplicável. Não
apresentar null, undefined ou NaN.

Validar Unicode com São José, Produção e Monitoração.

Executar validação visual e criar massa que force PDF multipágina.
Confirmar páginas 2+ sem sobreposição, texto cortado ou quebras
inválidas.

Segurança

PDF, metadados, filename, console e logs não podem conter JWT,
Authorization, senha, senhaHash, JWT_SECRET, Telegram token, connection
string, stack trace ou secrets. Não logar Blob/PDF.

Regressão CSV

Reexecutar no navegador os seis exports: Disponibilidade Equipamentos,
Disponibilidade Unidades, Incidentes, Medições, Latência e Notificações.
Validar 200, download real, BOM, UTF-8, header, filename, filtros, sort,
ausência de page/size/JWT e ausência de duplicação.

Excel e Formula Injection

Tentar localizar Microsoft Excel. Se disponível, abrir CSVs
representativos e validar UTF-8, acentuação, colunas, separador, datas,
vazios e Formula Injection com =, +, -, @, tab, CR e LF,
inclusive após whitespace. Se Excel realmente não estiver instalado,
registrar e repetir validação byte a byte/RFC 4180. Não afirmar ausência
sem tentar localizá-lo.

Limites CSV

Revalidar 100.000 linhas = 200 CSV e 100.001 = 422 JSON
EXPORT_LIMIT_EXCEEDED. No frontend: mensagem segura, nenhum arquivo
parcial/download e botão normalizado.

Performance e concorrência

Medir múltiplas execuções warm do fluxo Angular → backend → PostgreSQL →
renderer → HTTP → browser → arquivo. Registrar request, tempo até
download, bytes, páginas e memória aproximada quando possível; comparar
com R04.4.

Testar de forma controlada PDF+CSV e CSV+CSV simultâneos, verificando
integridade, filenames independentes, ausência de mistura e backend
saudável.

Responsividade e acessibilidade

Validar 320, 375, 390, 412, 768, 1024 e 1440, sem overflow da página.
Botão deve ser <button> real, ter nome acessível, teclado, foco
visível e disabled/loading corretos.

Console deve ficar sem erros Angular/template/CORS/HTTP inesperados ou
warnings relevantes.

Regressão Relatórios

Validar Visão Geral, Disponibilidade Equipamentos, Disponibilidade
Unidades, Incidentes, Medições, Latência e Notificações.

Testes e builds

Frontend:

npm test -- -- --watch=false
npm run build

Usar equivalente correto caso a versão do npm exija sintaxe diferente.
Esperado: 0 failures e BUILD SUCCESS.

Backend:

.\mvnw.cmd test
.\mvnw.cmd clean package

Esperado: 0 failures, 0 errors e BUILD SUCCESS.

Adicionar testes frontend para service PDF, Blob/response, período,
ausência page/size, botão exclusivo, loading/disabled, duplo clique,
filename/filename*, fallback/sanitização, .pdf,
create/revokeObjectURL, Content-Type,
400/401/403/PASSWORD_CHANGE_REQUIRED/500, ausência de download em erro e
preservação de estado.

Documentação

Revisar Docs/reports-export-architecture.md,
Docs/reports-export-api.md e Docs/reports-pdf-architecture.md.
Atualizar somente se necessário. Opcionalmente criar
Docs/reports-export-homologation.md se agregar valor sem duplicação.

Ao finalizar executar git status e git diff, relatando somente
arquivos efetivamente modificados/criados pela R04.5.

Proibições

Não gerar PDF no Angular/browser; não usar screenshot/DOM/HTML→PDF; não
recalcular KPI, disponibilidade ou P95; não buscar páginas em loop; não
persistir JWT/Blob; não logar Authorization/conteúdo; não adicionar PDF
às seis tabelas; não criar Visão Geral CSV; não criar fila/job/storage
sem evidência; não alterar contratos homologados preventivamente.

Critérios bloqueadores

R04.5 só pode ser homologada se ambiente 8080/4200/PostgreSQL 16 estiver
ativo; botão PDF existir somente na Visão Geral; download Angular real
funcionar; período e ausência de page/size estiverem corretos;
headers/filename/PDF/conteúdo/Unicode/multipágina/null safety estiverem
aprovados; matriz RBAC e erros estiver aprovada; uma interação gerar uma
request; segurança estiver aprovada; seis CSVs e limites 100000/100001
estiverem regredidos; Excel for testado se disponível; concorrência,
performance, responsividade, acessibilidade e console estiverem
aprovados; testes/builds frontend e backend estiverem verdes.
