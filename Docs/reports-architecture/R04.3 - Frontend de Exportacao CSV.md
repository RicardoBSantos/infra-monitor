R04.3 — Frontend de Exportação CSV — Infra Monitor

1. Objetivo

Implementar e homologar no frontend Angular a exportação CSV dos seis relatórios já suportados pelo backend R04.2:

Disponibilidade Equipamentos
Disponibilidade Unidades
Incidentes
Medições
Latência
Notificações

A implementação deve consumir os endpoints /export já homologados e baixar o arquivo sem reconstruir ou interpretar o CSV no Angular.

A Visão Geral continua fora do CSV V1.

2. Pré-condições

Considerar homologados:

R04.1 — Arquitetura de Exportação
R04.2 — Backend CSV

Fonte principal:

Docs/reports-export-architecture.md
Docs/reports-export-api.md

Não alterar backend sem bug real reproduzido.

3. Regra principal

O Angular NÃO gera CSV.

Fluxo correto:

filtros atuais
+ sort atual
  → request GET /export
  → response Blob
  → filename de Content-Disposition
  → download

É proibido:

percorrer páginas
concatenar registros
montar CSV
alterar conteúdo do Blob
recalcular dados

4. Endpoints

Consumir:

GET /api/v1/relatorios/disponibilidade/equipamentos/export
GET /api/v1/relatorios/disponibilidade/unidades/export
GET /api/v1/relatorios/incidentes/export
GET /api/v1/relatorios/medicoes/export
GET /api/v1/relatorios/latencia/export
GET /api/v1/relatorios/notificacoes/export

5. Service

Adicionar métodos tipados ao RelatorioApiService ou serviço equivalente já existente.

A resposta deve permitir acesso a:

Blob
headers
status

Usar observe: 'response' quando necessário.

Não adicionar Authorization manual.

Bearer continua exclusivamente via interceptor.

6. Filtros

Cada export deve usar EXATAMENTE os filtros atuais da respectiva área.

Não usar filtros antigos/stale.

Não exportar valores não selecionados.

Preservar:

inicio
fim
IDs
enums
sort

conforme cada endpoint.

7. Sort

Export deve respeitar o sort atual da tela.

Não criar sort alternativo específico para exportação.

Se usuário nunca escolheu sort, usar o default que o backend já define.

8. Paginação

NÃO enviar:

page
size

para endpoints /export.

Exportação representa todo o conjunto filtrado, limitado pelo backend.

9. Botão

Adicionar:

Exportar CSV

nas seis áreas.

Não adicionar na Visão Geral nesta fase.

10. Estado visual

Durante exportação:

loading específico do botão

Não bloquear toda a tela.

11. Duplo clique

Enquanto uma exportação da mesma área estiver em andamento:

desabilitar botão

ou estratégia equivalente.

Uma ação do usuário deve gerar:

uma request

Não permitir downloads concorrentes idênticos por duplo clique.

12. Estado da tela

Exportação NÃO deve:

resetar filtros
resetar sort
resetar paginação
limpar tabela
trocar aba

13. Blob

Tratar retorno como:

Blob

Não converter CSV em string e reconstruir arquivo.

14. Content-Disposition

Ler:

Content-Disposition

exposto pelo backend.

Suportar:

filename=
filename*=

Dar preferência correta a filename* quando presente.

\

16. Fallback filename

Se Content-Disposition estiver ausente/malformado:

usar fallback determinístico.

Exemplo:

medicoes_<inicio>_<fim>.csv

Nunca usar:

undefined.csv
null.csv

17. Object URL

Fluxo:

URL.createObjectURL(blob)
anchor.download
click
URL.revokeObjectURL(...)

Revogar Object URL após uso.

Evitar leak.

18. Erros JSON em endpoint Blob

Atenção: endpoints de exportação retornam:

CSV Blob em sucesso
JSON ErroResposta em erro

Quando HttpClient estiver configurado com responseType: 'blob', erros podem chegar como Blob JSON.

Implementar parsing seguro do erro para recuperar:

code
message
status

sem quebrar o tratamento global.

19. Erros obrigatórios

Tratar:

400 INVALID_REQUEST
401 UNAUTHORIZED
403 FORBIDDEN
403 PASSWORD_CHANGE_REQUIRED
404 RESOURCE_NOT_FOUND
422 EXPORT_LIMIT_EXCEEDED
500 INTERNAL_ERROR

20. EXPORT_LIMIT_EXCEEDED

Mostrar mensagem clara.

Exemplo conceitual:

A exportação excede o limite permitido. Reduza o período ou aplique mais filtros.

Não tentar automaticamente paginar/exportar em partes.

21. 401/403

Preservar comportamento já homologado.

401 → fluxo global atual
403 → sessão preservada
PASSWORD_CHANGE_REQUIRED → fluxo atual

Não criar lógica paralela conflitante.

22. 500

Mensagem segura.

Não mostrar:

stack trace
exception
conteúdo interno

23. Success feedback

opcionalmente mostrar feedback discreto.
