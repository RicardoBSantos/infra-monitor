R04.4 --- PDF Consolidado da Visão Geral --- Backend e Arquitetura

Objetivo

Projetar, implementar e homologar no backend Spring Boot a exportação
server-side de um PDF consolidado da Visão Geral. Considerar
homologadas R02, R03 e R04.1--R04.3. A integração Angular do PDF
pertence à R04.5.

Referências: Docs/reports-architecture/reports-architecture.md,
Docs/reports-dashboard-analytics.md,
Docs/reports-export-architecture.md e Docs/reports-export-api.md.

Antes de alterar, executar git status e git diff e preservar
mudanças preexistentes.

Escopo e regras analíticas

Endpoint preferencial:

GET /api/v1/relatorios/visao-geral/export/pdf?inicio=...&fim=...

O PDF V1 deve conter: identificação/título, período, data de geração,
KPIs globais de Incidentes abertos, Medições com falha e Notificações
com falha, Top 5 global de Unidades por pior disponibilidade, Top 5
global de Equipamentos críticos e Latência por Monitor.

Nenhuma métrica global pode ser calculada com página parcial. É proibido
carregar páginas em loop, usar content.size() como count, fazer média
simples de disponibilidades, recalcular P95 em Java/template, inferir
disponibilidade por medição isolada ou gerar PDF a partir do
Angular/DOM/screenshot.

Preservar a semântica homologada: ponderação temporal de Unidade,
CALCULADO, SEM_DADOS, SEM_MONITORAMENTO, PRECISA, INFERIDA e
NULLS LAST. Ausência de dados nunca vira 0%. Latência usa
min/avg/max/p95/count do backend/PostgreSQL.

O período é obrigatório, explícito e limitado a 31 dias, sem truncamento
silencioso.

Arquitetura obrigatória

Antes de implementar, auditar e documentar a biblioteca PDF Java
escolhida, incluindo versão, licença, compatibilidade com Java/Spring
Boot, Unicode, tabelas, paginação, manutenção e segurança.

Decidir tecnicamente entre PDF programático e template server-side →
PDF. Preferir solução simples, sustentável e sem dependência de
Chrome/frontend. Não introduzir fila/job/storage sem benchmark que
demonstre necessidade.

Criar Docs/reports-pdf-architecture.md documentando
biblioteca/licença, estratégia, endpoint, modelo, conteúdo, limites,
timeout, RBAC, segurança, auditoria, consistência e performance.

Separar coleta de dados, DTO/modelo explícito do relatório e
renderer/template versionado. É proibido passar entidades JPA ao
renderer ou espalhar strings de layout pelo service.

Layout mínimo

Cabeçalho com Infra Monitor, título "Visão Geral", período e instante de
geração. Exibir os três KPIs, tabela de ranking de Unidades, tabela de
Equipamentos críticos e tabela de Latência por Monitor. Incluir legenda
textual dos estados analíticos quando necessário.

Gráficos não são obrigatórios no V1. Não adicionar dependências de
gráfico sem ganho real. Informação não pode depender exclusivamente de
cor.

Nunca imprimir null, undefined ou NaN; usar representação segura
como —. Disponibilidade calculada deve manter duas casas.
Unicode/acentuação deve funcionar.

HTTP

Sucesso:

HTTP 200

Content-Type: application/pdf

Content-Disposition: attachment

filename e filename*

Nome determinístico e seguro, por exemplo
visao-geral_2026-08-01_2026-08-26.pdf.

Erros devem continuar como JSON ErroResposta. Não retornar PDF para
erro de validação.

RBAC e segurança

Preservar:

ADMIN: permitido

OPERADOR: permitido

VISUALIZADOR: permitido

sem JWT: 401

conta inativa: 401

PASSWORD_CHANGE_REQUIRED: 403

O PDF/log/filename não pode conter JWT, Authorization, senha, senhaHash,
JWT_SECRET, token Telegram, stack trace, connection string ou secrets.

Implementar/reutilizar auditoria estruturada de exportação com início,
sucesso e falha, correlationId, userId, papel, período, duração, bytes,
timestamp e resultado. Não logar conteúdo do PDF.

Consistência e PostgreSQL

Usar PostgreSQL 16 real/Testcontainers. O PDF deve representar um
conjunto coerente; avaliar snapshot/transação read-only para impedir
contradição entre KPIs e rankings.

Se houver queries novas/substancialmente diferentes, executar
EXPLAIN (ANALYZE, BUFFERS). Não criar índices sem evidência.

Criar teste bloqueador com massa maior que a página padrão para provar
que KPIs/rankings são globais e não derivados da primeira página.

Testes obrigatórios

Cobrir renderer/modelo e integração HTTP com PostgreSQL real:

assinatura %PDF;

arquivo não vazio e estruturalmente válido;

título/período/KPIs/tabelas;

Unicode e acentuação (São José, Produção, Monitoração);

null safety;

múltiplas páginas se aplicável;

estados analíticos e qualidade;

latência e P95 sem recálculo;

Content-Type;

Content-Disposition;

filename/filename*;

período ausente/invertido/igual/válido/>31 dias;

matriz RBAC completa;

erros como JSON;

massa determinística com KPIs/rankings conhecidos;

teste contra página parcial;

regressão dos seis exports CSV.

Não usar OCR como teste principal.

Benchmark

Medir múltiplas execuções warm e registrar: massa, tempo de consultas,
tempo de geração, tempo total, bytes, memória aproximada, páginas e
linhas/tabelas. Fechar com evidência a decisão síncrona/assíncrona.

O PDF é consolidado/executivo; não despejar dezenas de milhares de
medições. CSV continua sendo o formato detalhado.

Ambiente obrigatório

Antes dos smoke tests:

Backend atualizado: http://localhost:8080

Frontend atualizado: http://127.0.0.1:4200

Se necessário: verificar portas → encerrar processos antigos → subir
PostgreSQL 16 isolado → subir backend atualizado → aguardar
/actuator/health = 200 → subir frontend atualizado → aguardar HTTP 200
→ somente então executar smoke.

Não marcar ambiente pendente sem tentar subi-lo.

A R04.4 não implementa botão Angular. O frontend deve ficar ativo para
regressão e preparação da R04.5.

Smoke e regressão

Autenticar, chamar o endpoint PDF, salvar o arquivo, validar headers/PDF
e ausência de secrets. Sem JWT deve retornar 401 JSON.

Executar regressão mínima dos seis CSVs e preservar todos os endpoints
analíticos/Visão Geral.

Comandos finais

Backend:

.\mvnw.cmd test

.\mvnw.cmd clean package

Esperado: 0 failures, 0 errors e BUILD SUCCESS.

Se contrato compartilhado, CORS/security ou frontend forem alterados,
executar também:

npm test -- -- --watch=false

npm run build

Fora de escopo

Não implementar: botão Angular de PDF, PDF individual das seis tabelas,
Visão Geral CSV, email, fila/storage sem evidência, agendamento,
Telegram ou R04.5.

Critérios bloqueadores

R04.4 só pode ser homologada com: arquitetura documentada;
biblioteca/licença auditadas; geração server-side; endpoint; modelo
explícito; renderer/template versionado; período de 31 dias; KPIs e
rankings globais corretos; latência/P95 corretos; estados analíticos
preservados; null safety; Unicode; headers PDF; RBAC; segurança;
auditoria; decisão síncrona/assíncrona; benchmark; PostgreSQL 16 real;
teste contra página parcial; PDF válido; smoke; regressão CSV; suíte
completa e clean package.
