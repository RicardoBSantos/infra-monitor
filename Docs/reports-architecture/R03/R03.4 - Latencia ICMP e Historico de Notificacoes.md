R03.4 --- Latência ICMP e Histórico de Notificações --- Infra Monitor

1. Objetivo

Implementar e homologar no frontend Angular as duas áreas analíticas
restantes do backend de Relatórios:

Latência ICMP;

Histórico de Notificações.

A fase deve consumir exclusivamente os endpoints já homologados:

GET /api/v1/relatorios/latencia
GET /api/v1/relatorios/notificacoes

A implementação deve permanecer integrada à rota:

/relatorios

sem criar módulo paralelo de UI.

2. Pré-condições

Considerar homologados:

R02 — Backend de Relatórios
R03.1 — Fundação de Relatórios
R03.2 — Disponibilidade por Equipamentos e Unidades
R03.3 — Histórico de Incidentes e Medições

Não reabrir fases anteriores salvo regressão real.

3. Regra obrigatória de ambiente

Antes de qualquer smoke/browser, garantir:

Backend:

http://localhost:8080

Frontend:

http://127.0.0.1:4200

Se os serviços não estiverem ativos:

verificar portas 8080 e 4200;

encerrar processos antigos/desatualizados;

subir PostgreSQL isolado de teste;

subir backend atualizado em localhost:8080;

aguardar /actuator/health = 200;

subir frontend atualizado em 127.0.0.1:4200;

aguardar frontend = 200;

somente depois iniciar smoke/browser.

Não encerrar a fase alegando ambiente indisponível sem antes tentar
subir os serviços.

4. Fontes de verdade

Antes de codificar, auditar:

LatenciaIcmpResponse
HistoricoNotificacaoResponse
RelatorioApiService
RelatorioController
RelatorioService
api-enums.ts
relatorios.component.ts/html/scss

Usar apenas campos e filtros reais.

Não inventar propriedade ausente no backend.

5. Regra principal

O Angular NÃO calcula:

minLatenciaMs
avgLatenciaMs
maxLatenciaMs
p95LatenciaMs
count
status da Notificação
tentativas
datas de envio

Esses valores são fornecidos pelo backend.

Especialmente:

p95LatenciaMs

não pode ser recalculado no frontend.

PARTE A --- LATÊNCIA ICMP

6. Endpoint

Consumir:

GET /api/v1/relatorios/latencia

via:

RelatorioApiService.getLatencia(...)

7. DTO

Usar:

LatenciaIcmpResponse

fiel ao backend.

Campos homologados incluem:

minLatenciaMs
avgLatenciaMs
maxLatenciaMs
count
p95LatenciaMs

e campos de contexto reais como Unidade/Equipamento/Monitor quando
presentes no DTO.

9. Formatação

Latências inteiras:

11 ms
95 ms

Média, se decimal:

usar formatação coerente com o DTO real.

Não forçar inteiro se backend retorna decimal.

10. Valores nulos

Quando qualquer métrica nullable vier null:

—

Nunca:

0 ms
NaN
undefined
null

11. Filtros Latência

Implementar somente filtros reais.

somente após auditoria.

12. Dependências

Reutilizar hierarquia:

Unidade
→ Equipamento
→ Monitor

Mudança de Unidade:

limpa Equipamento
limpa Monitor
atualiza lookup

Mudança de Equipamento:

limpa Monitor
atualiza lookup

Obrigatório.

inicio ausente
fim ausente
inicio > fim
inicio = fim
>90 dias

permanece autoridade final.
