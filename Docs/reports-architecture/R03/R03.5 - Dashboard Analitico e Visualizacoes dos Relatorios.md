2. Regra arquitetural principal

O Angular NÃO pode fabricar métricas globais a partir de páginas parciais.

É proibido:

buscar page=0,size=20
→ somar percentuais
→ chamar isso de disponibilidade global

Também é proibido:

buscar primeira página de incidentes
→ contar status
→ chamar isso de total do período

Toda visualização precisa ser sustentada por uma destas condições:

A. backend já retorna a métrica agregada correta;
B. endpoint retorna o universo completo necessário de forma segura;
C. backend possui endpoint específico para a agregação;
D. visualização representa apenas a página atual e isso é explicitamente indicado.

Preferir A ou C.

5. Regra obrigatória de ambiente

Antes de smoke/browser:

Backend:

http://localhost:8080

Frontend:

http://127.0.0.1:4200

Se não estiverem ativos:

verificar portas 8080/4200;

encerrar processos antigos;

subir PostgreSQL isolado;

subir backend atualizado em 8080;

aguardar /actuator/health = 200;

subir frontend atualizado em 4200;

aguardar frontend = 200;

só então executar browser.

Não encerrar alegando ambiente indisponível sem tentar subir os serviços.

6. Browser obrigatório

Usar Chrome/Chromium + Playwright.

Browser/Network/Console/Responsividade não podem ser homologados apenas por teste unitário.

7. Auditoria — Disponibilidade por Unidade

Avaliar:

ranking de Unidades por disponibilidade;

comparação entre Unidades;

tempo monitorado por Unidade;

tempo indisponível;

incidentes;

equipamentos monitorados;

sem monitoramento;

sem dados.

Se os dados já vêm agregados por Unidade, classificar como implementável.

Não recalcular média entre equipamentos.

8. Auditoria — Disponibilidade por Equipamento

Avaliar:

ranking de Equipamentos por disponibilidade;

piores Equipamentos;

melhores Equipamentos;

tempo indisponível;

incidentes;

estado analítico;

qualidade.

Ranking global só pode usar sort server-side + page 0 + size N.

9. Auditoria — Incidentes

Avaliar:

últimos Incidentes;

Incidentes abertos;

Incidentes fechados;

ranking por duração.

Não calcular totais globais a partir de página parcial.

Se totalElements sob filtro representa universo filtrado, pode ser usado como KPI.

10. Auditoria — Medições

Avaliar:

últimas Medições;

falhas recentes;

sucessos recentes.

Não criar taxa global de sucesso/falha baixando páginas.

11. Auditoria — Latência

Avaliar:

ranking por média;

ranking por máxima;

comparação min/avg/max/p95.

P95 não pode ser ranking global sem sort backend correspondente.

12. Auditoria — Notificações

Avaliar:

últimas Notificações;

count por status;

count por canal;

count por tipoEvento.

Se usar totalElements de filtro para KPI, documentar semanticamente.

16. Visão Geral

Adicionar aba:

Visão Geral

dentro de /relatorios.

Não criar nova rota top-level.

17. Período

Implementar período compartilhado explícito.

Respeitar limites:

Disponibilidade: 365 dias
Incidentes: 365 dias
Medições: 31 dias
Latência: 90 dias
Notificações: 365 dias

Não truncar silenciosamente.

18. KPIs

Implementar somente KPIs aprovados na auditoria.

Possíveis, se suportados:

Equipamentos sem monitoramento

Equipamentos sem dados

Incidentes abertos

Medições com falha

Notificações com falha

19. KPI via totalElements

Pode usar totalElements de request filtrada se representar o universo correto.

Não baixar todas as páginas.

20. Ranking de Unidades

Se suportado, exibir Unidade + disponibilidadePercentual com sort server-side.

21. Top Equipamentos críticos

Usar:

sort=disponibilidadePercentual,asc
page=0
size=N

Não tratar null como 0.

22. SEM_DADOS / SEM_MONITORAMENTO

Preservar NULLS LAST do backend.

Não considerar null como pior que 0%.

Se suportado, exibir:

avg
max
p95

24. Incidentes visual

Implementar somente widgets aprovados na auditoria.

Não criar série temporal sem agregação backend.

25. Notificações visual

Implementar somente widgets aprovados na auditoria.

26. Biblioteca de gráficos

Verificar dependências existentes antes de adicionar biblioteca.

Se já houver charts, reutilizar.

Se não houver, escolher solução leve e compatível.

27. Bundle

Medir impacto:

lazy chunk Relatórios antes/depois

Preferir lazy loading.

28. HTML/CSS quando suficiente

Para rankings simples, preferir HTML/CSS acessível em vez de biblioteca pesada.

29. Acessibilidade

Todo gráfico precisa de alternativa textual/tabular.

Garantir:

título;

descrição;

unidades;

legenda;

valores acessíveis;

não depender só de cor.

30. Loading parcial

Cada widget pode carregar independentemente.

31. Error parcial
