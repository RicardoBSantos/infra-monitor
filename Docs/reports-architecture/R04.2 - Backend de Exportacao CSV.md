R04.2 — Backend de Exportação CSV — Infra Monitor

1. Objetivo

Implementar no backend Spring Boot a exportação CSV dos seis relatórios tabulares definidos e homologados na R04.1:

Disponibilidade por Equipamentos
Disponibilidade por Unidades
Incidentes
Medições
Latência
Notificações

A implementação deve seguir fielmente:

Docs/reports-export-architecture.md

A Visão Geral permanece fora do CSV V1.

2. Pré-condições

Considerar homologados:

R02 — Backend de Relatórios
R03 — Frontend de Relatórios
R04.1 — Arquitetura e Contratos de Exportação

Não alterar contratos já homologados sem bug real.

3. Regra principal

A exportação é BACKEND-DRIVEN.

É proibido:

paginar em loop internamente
carregar todas as páginas em memória
serializar entidades JPA
gerar CSV no Angular

A implementação deve usar:

count prévio
consulta/exportação server-side
cursor/streaming
DTO/projeção explícita
memória aproximadamente constante

4. Endpoints obrigatórios

Implementar:

GET /api/v1/relatorios/disponibilidade/equipamentos/export
GET /api/v1/relatorios/disponibilidade/unidades/export
GET /api/v1/relatorios/incidentes/export
GET /api/v1/relatorios/medicoes/export
GET /api/v1/relatorios/latencia/export
GET /api/v1/relatorios/notificacoes/export

Não criar endpoint genérico único nesta fase.

6. Sort

A exportação deve respeitar o sort solicitado pelo usuário usando apenas whitelist homologada.

Defaults:

Disponibilidade Equipamentos: equipamentoNome,asc
Disponibilidade Unidades: unidadeNome,asc
Incidentes: iniciadoEm,desc
Medições: executadoEm,desc
Latência: monitorNome,asc
Notificações: createdAt,desc

Sort inválido:

400 INVALID_REQUEST

Não aceitar SQL arbitrário.

7. Sem paginação da tela

Os endpoints de exportação NÃO recebem:

page
size

A exportação deve conter todo o conjunto filtrado, respeitando o limite operacional.

8. Limite de linhas

Limite máximo:

100.000 linhas de dados

Header não conta.

Fluxo obrigatório:

1. validar filtros;
2. fazer count real;
3. se count >100000:
   abortar antes de iniciar body CSV;
4. retornar JSON de erro.

9. Erro de limite

Quando exceder:

HTTP 422
code: EXPORT_LIMIT_EXCEEDED

Responder com:

ErroResposta/ApiError JSON

Nunca iniciar CSV parcial.

10. Limites temporais

Preservar:

Disponibilidade: 365 dias
Incidentes: 365 dias
Medições: 31 dias
Latência: 90 dias
Notificações: 365 dias

Validações existentes devem ser reutilizadas.

11. Consistência entre count e exportação

Count e streaming devem operar em snapshot/transação consistente quando necessário.

Evitar:

count=99999
dados mudam
stream retorna 100005

Documentar estratégia transacional.

12. Streaming

Preferir streaming HTTP real.

Não montar:

String gigante
byte[] gigante
List com 100000 DTOs

em memória.

Avaliar:

StreamingResponseBody
OutputStream
cursor JDBC
fetch size
query forward-only

ou solução equivalente segura.

13. PostgreSQL cursor

Se usar JDBC:

configurar para permitir streaming/cursor real no PostgreSQL.

Auditar:

autocommit
fetchSize
transação
ResultSet

Não assumir que fetchSize sozinho garante cursor.

14. DTO/projeção

Criar contratos explícitos de exportação quando necessário.

Não exportar entidade JPA.

Pode reutilizar DTO analítico se adequado, mas a ordem/serialização CSV deve ser explícita.

15. CSV — encoding

Obrigatório:

UTF-8
BOM presente

EF BB BF

no início do arquivo.

16. CSV — Content-Type

Responder:

text/csv; charset=UTF-8

17. CSV — RFC 4180

Usar:

vírgula
CRLF
aspas duplas
escape de aspas como ""

Campos contendo:

vírgula
aspas
CR
LF

devem ser corretamente quoted/escaped.

18. CSV Injection

Obrigatório neutralizar strings potencialmente perigosas iniciadas por:

inclusive após espaços iniciais.

Estratégia homologada:

prefixar apóstrofo

quando aplicável.

Não alterar semântica de campos numéricos reais.

20. Null

CSV representa null como:

campo vazio

Não escrever:

null
undefined
NaN
—

21. Datas

Todas as datas:

ISO-8601 UTC

com Z.

Exemplo:

2026-08-25T14:32:10Z

Não exportar timezone local ambíguo.

22. Decimais

Usar:

ponto decimal
sem locale
sem notação científica

Preservar escala coerente com o contrato.

23. Enums

Exportar strings estáveis do backend.

Não traduzir.

24. Content-Disposition

Responder:

attachment

com:

filename=
filename*=

seguros.

Padrão:

<relatorio>_<inicio-yyyy-MM-dd>_<fim-yyyy-MM-dd>.csv

Sanitizar.

25. CORS

Garantir que frontend possa ler:

Content-Disposition

Adicionar:

Access-Control-Expose-Headers: Content-Disposition

na configuração CORS centralizada.

Preservar:

credentials=false
wildcard=false
Authorization permitido
