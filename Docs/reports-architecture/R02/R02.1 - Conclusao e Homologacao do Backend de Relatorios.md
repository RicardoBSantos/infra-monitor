R02.1 --- Conclusão e Homologação do Backend de Relatórios --- Infra Monitor

1. Objetivo

Concluir e homologar a R02 sem ampliar seu escopo e sem recomeçar a
implementação do zero.

A R02 terminou como BLOQUEADO. Já existem migration, entidades,
repository, serviços e controller iniciais. A R02.1 deve auditar esse
código, preservar o que estiver correto, corrigir o que estiver
incorreto e implementar apenas o que falta para cumprir integralmente a
especificação original da R02 e a arquitetura aprovada na R01.

Ao final, somente será permitido declarar R02 HOMOLOGADA se
implementação, testes, build, smoke tests e regressões obrigatórias
tiverem sido efetivamente validados.

5. Corrigir Clock

A tentativa de substituir a injeção por Clock.systemUTC() não deve
permanecer como solução definitiva para operações temporais de domínio.

As operações do ciclo de janela_monitoramento precisam usar um Clock
Spring testável.

Auditar os beans existentes, incluindo monitoringClock e
notificationClock.

Usar o Clock semanticamente correto para o ciclo de monitoramento,
preferencialmente monitoringClock, com:

@Qualifier("monitoringClock")

ou solução equivalente explicitamente não ambígua.

Não criar outro bean sem necessidade.

Não reintroduzir:

NoUniqueBeanDefinitionException

Testes devem conseguir substituir/controlar o instante.

6. Homologar migration V13

Auditar V13__create_janela_monitoramento.sql.

Confirmar:

FK válida;

monitor_id NOT NULL;

inicio_em NOT NULL;

fim_em >= inicio_em;

origem válida;

unicidade parcial para somente uma janela aberta por Monitor;

índice temporal apropriado;

backfill idempotente/determinístico;

nenhuma utilização de updated_at;

Monitor sem Medição não recebe janela inventada.

Backfill legado:

inicio = max(monitor.createdAt, primeiraMedicao.executadoEm)
fim = ultimaMedicao.executadoEm + intervaloSegundos
origem = INFERIDA

Se a migration existente não cumprir exatamente isso, corrigi-la somente
se ainda for seguro no contexto do projeto de desenvolvimento. Se já
houver possibilidade de V13 ter sido aplicada em ambiente persistente
relevante, não reescrever silenciosamente uma migration aplicada: criar
migration corretiva subsequente.

7. Ciclo de vida de Monitor

Homologar transacionalmente:

Criação ativa

Abrir:

origem = PRECISA
inicioEm = clock.instant()
fimEm = null

Criação inativa

Não abrir janela.

Desativação

Encerrar exatamente a janela aberta no instante da operação.

Reativação

Abrir nova janela PRECISA.

Idempotência

Não criar duas janelas abertas.

Operações repetidas não podem corromper histórico.

Janelas fechadas não podem ser reescritas.

8. Ciclo de vida de Equipamento

Desativação

Encerrar janelas abertas dos Monitores pertencentes ao Equipamento.

Reativação

Abrir janela somente para Monitor:

monitor.ativo = true

Não alterar monitor.ativo.

Monitor administrativamente inativo não ganha janela.

Tudo deve ocorrer na mesma transação da alteração administrativa
correspondente.

Criar testes de rollback/atomicidade quando aplicável.

9. Regra oficial de disponibilidade

É proibido implementar disponibilidade como razão de quantidade de
Medições.

A fórmula permanece temporal.

Para cada janela:

inicioEfetivo =
max(
inicioRelatorio,
inicioJanela,
primeiraMedicao.executadoEm dentro da janela
)

fimEfetivo =
min(
fimRelatorio,
fimJanela quando existir
)

Somente:

inicioEfetivo < fimEfetivo

contribui.

Janela sem Medição não contribui para tempo monitorado.

10. Normalização das janelas

Garantir que janelas elegíveis não provoquem dupla contagem.

Se houver intervalos sobrepostos por dado legado ou situação defensiva,
normalizá-los antes da soma.

Preferir solução SQL PostgreSQL robusta:

CTE;

window functions;

gaps-and-islands;

range/multirange quando compatível.

Documentar a estratégia escolhida.

11. União dos Incidentes

Esta é uma exigência obrigatória da homologação.

Para cada Monitor:

obter Incidentes que intersectam o período;

tratar Incidente aberto como terminando em fimRelatorio;

intersectar cada Incidente com as janelas efetivamente monitoradas;

descartar interseções vazias;

unir intervalos sobrepostos ou contíguos conforme semântica
[inicio,fim);

somar a duração da união.

Nunca fazer:

SUM(duração de cada incidente)

sem união prévia.

Exemplo obrigatório de teste:

janela monitorada: 10:00–11:00
incidente A:       10:10–10:30
incidente B:       10:20–10:40

indisponibilidade correta = 30 minutos
não 40 minutos

12. Fórmula final

tempoMonitorado =
duração da união das janelas efetivamente monitoradas

tempoIndisponivel =
duração da união(
incidentes
∩ janelasMonitoradas
∩ período
)

tempoDisponivel =
tempoMonitorado - tempoIndisponivel

Se:

tempoMonitorado > 0

então:

disponibilidadePercentual =
round(
tempoDisponivel / tempoMonitorado * 100,
2,
HALF_UP
)

Caso contrário:

disponibilidadePercentual = null

Nunca permitir resultado abaixo de 0 ou acima de 100 por dupla contagem.
