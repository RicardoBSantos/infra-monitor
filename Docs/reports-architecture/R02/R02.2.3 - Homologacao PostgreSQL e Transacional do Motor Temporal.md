R02.2.3 --- Homologação PostgreSQL e Transacional do Motor Temporal

Infra Monitor

1. Objetivo

Encerrar definitivamente a R02.2 por meio de homologação executável da
persistência e do ciclo de vida do motor temporal.

Esta fase não é uma nova fase de desenvolvimento arquitetural. O
núcleo matemático já foi comprovado na R02.2.1 e a camada tipada por
Equipamento (DisponibilidadeEquipamentoTemporalService) foi criada na
R02.2.2.

A R02.2.3 deve provar, com testes reais, que o fluxo abaixo funciona:

PostgreSQL
→ migration V13
→ JanelaMonitoramento
→ ciclo administrativo Monitor/Equipamento
→ Medição/Incidente persistidos
→ DisponibilidadeEquipamentoTemporalService
→ DisponibilidadeTemporalCalculator
→ resultado tipado

A regra desta fase é:

CRIAR TESTE
→ EXECUTAR
→ OBSERVAR
→ CORRIGIR SOMENTE SE NECESSÁRIO
→ EXECUTAR NOVAMENTE

Não implementar funcionalidade nova antes de existir teste que demonstre
a necessidade.

3. Regra de escopo

3.1 Permitido

É permitido:

criar testes;

criar fixtures/builders de teste;

ajustar configuração Testcontainers;

corrigir migrations se teste provar defeito;

corrigir repositories/queries se teste provar defeito;

corrigir serviços existentes se teste provar defeito;

corrigir transações se teste provar defeito;

corrigir a camada tipada existente;

alterar o calculador apenas diante de bug persistido reproduzível.

3.2 Proibido

Não implementar nesta fase:

agregação por Unidade;

novos endpoints de Relatórios;

CSV;

Angular;

gráficos;

paginação final;

sort final;

relatório final de Incidentes;

relatório final de Medições;

relatório final de Latência;

relatório final de Notificações;

refatorações cosméticas amplas;

nova arquitetura paralela.

4. Infraestrutura de testes

Usar PostgreSQL real, preferencialmente a infraestrutura Testcontainers
já existente no projeto.

Não substituir por H2.

Se Docker/Testcontainers não iniciar:

diagnosticar;

verificar Docker;

tentar corrigir configuração local/teste;

registrar o erro real.

Somente declarar bloqueio externo se o ambiente realmente impedir
PostgreSQL/Testcontainers.

5. Teste da migration V13

Criar teste dedicado de migration/schema.

Validar:

janela_monitoramento existe
monitor_id possui FK
inicio_em é obrigatório
fim_em aceita null
fim_em >= inicio_em
origem aceita valores válidos
origem inválida é rejeitada, se protegida por constraint
índice parcial de janela aberta existe/funciona

O teste deve executar contra PostgreSQL.

6. Índice parcial

Executar comportamento real:

Monitor X

A = [T0, null)
→ INSERT permitido

B = [T1, null)
→ INSERT rejeitado

fechar A em T1

B = [T2, null)
→ INSERT permitido

A rejeição deve vir da proteção do banco.

Critério:

nunca duas janelas abertas para o mesmo Monitor

7. Backfill V13

Homologar o backfill com migration real.

Cenário BF1

monitor.createdAt = 09:00
primeira Medição = 09:15
última Medição = 10:00
intervaloSegundos = 60

Esperado:

inicio = 09:15
fim = 10:01
origem = INFERIDA

Cenário BF2

monitor.createdAt = 09:30
primeira Medição = 09:15
última Medição = 10:00
intervaloSegundos = 60

Esperado:

inicio = 09:30
fim = 10:01
origem = INFERIDA

Cenário BF3

Monitor sem Medição.

Esperado:

nenhuma janela inferida

Regras adicionais

Confirmar:

backfill nunca cria janela aberta
updatedAt não participa da fórmula

8. Ciclo de Monitor

Usar Clock controlável via:

@Qualifier("monitoringClock")

M1 --- criação ativa

T0:

criar Monitor ativo

Esperado:

1 janela PRECISA
inicio=T0
fim=null

M2 --- criação inativa

T0:

criar Monitor inativo

Esperado:

0 janelas abertas

M3 --- desativação

Monitor ativo criado em T0
desativado em T1

Esperado:

janela = [T0,T1)

M4 --- reativação

reativar em T2

Esperado:

janela antiga = [T0,T1)
nova janela = [T2,null)
origem nova = PRECISA

M5 --- histórico

Depois de novo ciclo, janelas fechadas antigas não podem ser alteradas.

M6 --- unicidade

Nenhuma operação pode resultar em duas janelas abertas.

9. Ciclo de Equipamento

Criar Equipamento com:

Monitor A ativo
Monitor B ativo

ambos com janela aberta.

E1 --- desativação

Em T1:

desativar Equipamento

Esperado:

janela A fecha em T1
janela B fecha em T1

E2 --- reativação seletiva

Antes de reativar:

Monitor A.ativo = true
Monitor B.ativo = false

Em T2:

reativar Equipamento

Esperado:

Monitor A → nova janela [T2,null)
Monitor B → nenhuma nova janela

E3 --- preservação administrativa

Confirmar explicitamente:

reativar/desativar Equipamento não modifica monitor.ativo

10. Rollback transacional

Criar teste de integração real.

A operação escolhida deve alterar:

estado administrativo
+
janela_monitoramento

Forçar uma exceção depois de uma das alterações e antes da conclusão.

Após rollback, abrir nova leitura/transação e verificar:

estado administrativo original
janela original
nenhuma janela parcial
nenhuma alteração intermediária persistida

Não homologar com Mockito.
