R02.4.2 --- Paginação e Sort Server-side da Disponibilidade --- Infra Monitor

1. Objetivo

Resolver exclusivamente o último gargalo estrutural da R02.4: paginação
e ordenação global server-side dos relatórios de Disponibilidade.

A R02.4.2 deve tratar somente:

GET /api/v1/relatorios/disponibilidade/equipamentos;

GET /api/v1/relatorios/disponibilidade/unidades;

COUNT real;

LIMIT/OFFSET;

sort global por campos simples;

sort global por métricas calculadas;

preservação de SEM_MONITORAMENTO;

preservação de SEM_DADOS;

teste real 25/10;

teste de ordenação global por disponibilidade;

testes de asc/desc e sort inválido;

regressão dos resultados temporais homologados.

Não implementar HTTP/RBAC/smoke amplo nesta fase. Isso ficará para
R02.4.3.

2. Pré-condições homologadas

Considerar como verdade:

R02.2 HOMOLOGADA
R02.3 HOMOLOGADA

O motor temporal já está comprovado e não deve ser reescrito.

Já estão homologados:

fórmula temporal;

união de janelas;

união de Incidentes;

SEM_MONITORAMENTO;

SEM_DADOS;

PRECISA;

INFERIDA;

múltiplos Monitores;

média ponderada por Unidade;

DTOs tipados.

Não reabrir essas regras.

3. Estado recebido da R02.4.1

Já concluído

sort server-side de Latência;

sort server-side de Notificações;

whitelist SQL de ambos;

documentação parcialmente atualizada;

PARTE A --- DISPONIBILIDADE EQUIPAMENTOS

5. Contrato

Endpoint:

GET /api/v1/relatorios/disponibilidade/equipamentos

Uma linha por Monitor ICMP, mais a representação SEM_MONITORAMENTO
quando aplicável.

Filtros já definidos:

inicio
fim
unidadeId
equipamentoId
monitorId
tipoEquipamentoId
page
size
sort

6. Sort por campos simples

Campos:

equipamentoNome
unidadeNome
monitorNome

Estratégia aceitável:

SQL filtra candidatos
→ COUNT
→ ORDER BY
→ LIMIT/OFFSET
→ motor temporal calcula apenas os candidatos da página

Desde que:

a ordem seja global;

o count seja correto;

SEM_MONITORAMENTO não desapareça;

múltiplos Monitores continuem independentes.

7. Sort por métricas calculadas

Campos:

disponibilidadePercentual
tempoIndisponivelSegundos
tempoMonitoradoSegundos
incidentes

É proibido:

paginar candidatos
→ calcular métricas
→ ordenar apenas a página

A ordenação deve considerar o universo completo antes de:

LIMIT
OFFSET

8. Estratégia server-side para métricas

Implementar query/projection SQL que produza as métricas necessárias
antes de ordenar.

É permitido usar:

CTEs
window functions
native SQL
projections
NamedParameterJdbcTemplate
PostgreSQL range/multirange
gaps-and-islands

Reutilizar a semântica temporal homologada.

Não alterar a fórmula.

9. Consistência matemática

A query server-side usada para sort/paginação deve produzir os mesmos
valores do motor já homologado.

Criar teste cruzado:

resultado SQL
vs
DisponibilidadeTemporalCalculator / serviço homologado

para cenários conhecidos.

Se divergirem, o SQL está errado.

10. SEM_MONITORAMENTO

Equipamento sem Monitor ICMP deve permanecer elegível conforme contrato.

Para ordenação por métricas:

disponibilidadePercentual = null
tempos = null

Definir null ordering determinístico.

Sugestão:

NULLS LAST

para asc e desc, salvo decisão existente diferente.

Documentar.

11. Count real

totalElements deve representar o total de linhas analíticas filtradas.

Não usar:

content.size()

Nem carregar tudo em Java para contar.

PARTE B --- DISPONIBILIDADE UNIDADES

12. Contrato

Endpoint:

GET /api/v1/relatorios/disponibilidade/unidades

Filtros:

inicio
fim
unidadeId
page
size
sort

13. Sort simples

Campo:

unidadeNome

Pode ser paginado diretamente no banco.

14. Sort por métricas

Campos:

equipamentosTotal
equipamentosMonitorados
equipamentosSemMonitoramento
tempoIndisponivelSegundos
disponibilidadePercentual
incidentes

A query deve calcular o agregado global da Unidade antes de:

ORDER BY
LIMIT
OFFSET

Não paginar Unidades primeiro quando o sort depende de métrica
calculada.

15. Média ponderada preservada

A query SQL precisa manter:

tempoMonitoradoUnidade =
SUM(tempoMonitorado dos Monitores CALCULADO)

tempoIndisponivelUnidade =
SUM(tempoIndisponivel dos Monitores CALCULADO)

percentual =
tempoDisponivel / tempoMonitorado

Nunca:

AVG(percentual)

16. Contagens sem duplicação

Garantir que:

equipamentosTotal
equipamentosMonitorados
equipamentosSemMonitoramento
equipamentosSemDados

não sejam duplicados por JOIN com múltiplos Monitores/Incidentes.

Usar COUNT(DISTINCT ...) ou estratégia equivalente correta.

PARTE D --- ORDENAÇÃO GLOBAL

18. Cenário D2 --- disponibilidade global

Criar pelo menos 15 linhas analíticas com percentuais distintos.

Executar:

size=5
sort=disponibilidadePercentual,desc

Esperado:

page 0 contém exatamente as 5 maiores disponibilidades do universo total

Não apenas as maiores de um subconjunto pré-paginado.

PARTE F --- SORT INVÁLIDO

PARTE G --- NULL ORDERING

Documentar.

ORDER BY
