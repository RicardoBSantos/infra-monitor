disponibilidade definido na R01/R02, sem ampliar o escopo para os
demais relatórios.

O ciclo temporal deve usar bean Spring testável.

Usar o Clock de monitoramento com qualificação explícita, por exemplo:

@Qualifier("monitoringClock")

Não usar Clock.systemUTC() diretamente em serviço de domínio.

Não criar novo bean Clock sem necessidade.

Criar teste de contexto provando:

sem ambiguidade

7. Histórico legado

A regra oficial permanece:

inicioInferido =
max(
monitor.createdAt,
primeiraMedicao.executadoEm
)

fimInferido =
ultimaMedicao.executadoEm + intervaloSegundos

Origem:

INFERIDA

Monitor legado sem Medição:

não recebe janela inferida

O backfill não pode criar janela aberta histórica.

Deve ser idempotente/determinístico.

Criar teste de integração sobre PostgreSQL real/Testcontainers.

8. Ciclo temporal de Monitor

Criação ativa

abrir janela PRECISA
inicio = clock.instant()
fim = null

Criação inativa

não abrir janela

Desativação

encerrar janela aberta
fim = clock.instant()

Reativação

abrir nova janela PRECISA

Repetição

Operações repetidas não podem criar duas janelas abertas.

Janelas fechadas não podem ser reescritas.

Tudo transacional.

9. Ciclo temporal de Equipamento

Desativação

Encerrar as janelas abertas de todos os Monitores pertencentes ao
Equipamento.

Reativação

Abrir nova janela somente para:

monitor.ativo = true

Não alterar monitor.ativo.

Monitor administrativamente inativo não pode receber janela.

Tudo na mesma transação da operação de Equipamento.

10. Atomicidade

Criar teste provando que falha transacional não deixa:

equipamento/monitor com status alterado
+
janela em estado inconsistente

Usar rollback real.

11. Definição de janela efetivamente observável

Uma janela administrativa não significa automaticamente que todo seu
período é monitorado.

Para cada janela:

inicioEfetivo =
max(
inicioRelatorio,
inicioJanela,
primeiraMedicao.executadoEm dentro da janela
)

fimEfetivo =
min(
fimRelatorio,
fimJanela se fechada
)

Se:

inicioEfetivo >= fimEfetivo

a janela não contribui.

Janela sem Medição no intervalo:

não contribui

12. Semântica de intervalo

Usar semântica temporal consistente:

[inicio, fim)

Isto é:

inicio inclusivo
fim exclusivo

Documentar isso no código/testes.

Evitar dupla contagem em limites coincidentes.

13. União de janelas

Antes de calcular tempoMonitorado, unir janelas efetivas sobrepostas
ou contíguas quando necessário.

Objetivo:

tempoMonitorado =
duração da união das janelas efetivas

Nunca:

SUM(duração individual)

se isso puder duplicar tempo.

Implementar preferencialmente no PostgreSQL ou em algoritmo de domínio
claramente testado, sem depender de volume massivo em memória.

Na R02.2, a prioridade é correção matemática; documentar estratégia
escolhida.

14. Seleção de Incidentes

Selecionar apenas Incidentes do Monitor que possam intersectar o
período/janelas.

Incidente fechado:

[iniciadoEm, encerradoEm)

Incidente aberto:

[iniciadoEm, fimRelatorio)

Nunca considerar tempo posterior ao fim do relatório.

15. Interseção Incidente × janela

Para cada Incidente e janela efetiva:

inicioIntersecao =
max(inicioIncidente, inicioJanelaEfetiva)

fimIntersecao =
min(fimIncidenteEfetivo, fimJanelaEfetiva)

Somente se:

inicioIntersecao < fimIntersecao

o trecho contribui.

Incidente atravessando período sem janela ativa não pode contar nesse
trecho.

16. União de Incidentes

Depois de gerar as interseções:

unir intervalos sobrepostos

e, conforme semântica escolhida, intervalos contíguos podem ser fundidos
por equivalência de duração.

Nunca duplicar indisponibilidade.

17. Fórmula

tempoMonitoradoSegundos =
duração da união das janelas efetivas

tempoIndisponivelSegundos =
duração da união(
incidentes ∩ janelas efetivas
)

tempoDisponivelSegundos =
tempoMonitoradoSegundos - tempoIndisponivelSegundos

Se:

tempoMonitoradoSegundos > 0

então:

disponibilidadePercentual =
round(
tempoDisponivelSegundos
/ tempoMonitoradoSegundos
* 100,
2,
HALF_UP
)

Nunca permitir:

tempoIndisponivel > tempoMonitorado
percentual < 0
percentual > 100

18. Estado CALCULADO

Quando houver tempo monitorado observável:

estadoAnalitico = CALCULADO

Retornar tempos e percentual.

19. SEM_MONITORAMENTO

Equipamento sem Monitor ICMP:

estadoAnalitico = SEM_MONITORAMENTO

Resultado conceitual:

monitorId = null
monitorNome = null
tempoMonitoradoSegundos = null
tempoIndisponivelSegundos = null
tempoDisponivelSegundos = null
disponibilidadePercentual = null
incidentes = 0
qualidadeJanela = null

O Equipamento não pode simplesmente desaparecer da consulta interna
usada futuramente pelo endpoint.

20. SEM_DADOS

Monitor ICMP existe, mas não há tempo observável calculável no período.

Exemplos:

janela sem Medição
período anterior à primeira Medição
janela fora do período

Resultado:

estadoAnalitico = SEM_DADOS
tempos = null
percentual = null

Não retornar 0%.

21. Qualidade PRECISA

Se todo o tempo contribuinte deriva de janelas PRECISA:

qualidadeJanela = PRECISA

22. Qualidade INFERIDA

Se qualquer tempo contribuinte deriva de janela INFERIDA:

qualidadeJanela = INFERIDA

Esse comportamento conservador evita ocultar incerteza histórica.

23. Múltiplos Monitores

Disponibilidade deve continuar sendo calculada por Monitor.

Não consolidar dois Monitores ICMP do mesmo Equipamento em um percentual
único.

O motor deve conseguir produzir dois resultados independentes.
