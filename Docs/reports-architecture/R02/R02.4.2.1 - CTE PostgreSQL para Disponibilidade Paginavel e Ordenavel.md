R02.4.2.1 --- CTE PostgreSQL para Disponibilidade Paginável e Ordenável --- Infra Monitor

1. Objetivo

Implementar a representação SQL server-side da disponibilidade temporal
já homologada, de forma que os relatórios de Disponibilidade possam
finalmente suportar:

COUNT real;

ORDER BY global;

LIMIT/OFFSET;

paginação server-side;

sort por métricas calculadas;

consistência matemática com o motor temporal Java.

Esta fase não deve tratar HTTP, RBAC, smoke tests, CSV ou frontend.

O único objetivo é:

transformar a fórmula temporal já homologada
em uma query PostgreSQL equivalente

sem modificar o significado da disponibilidade.

2. Pré-condição

Considerar como oráculo já homologado:

DisponibilidadeTemporalCalculator
DisponibilidadeEquipamentoTemporalService
R02.2
R02.3

Resultados obrigatórios de referência:

B persistido:
tempoMonitorado = 3600
tempoIndisponivel = 1800
tempoDisponivel = 1800
percentual = 50.00
incidentes = 2

C persistido:
tempoMonitorado = 10800
tempoIndisponivel = 3600
tempoDisponivel = 7200
percentual = 66.67

U2:
percentual Unidade = 91.00

A SQL nova deve produzir exatamente os mesmos resultados.

3. Regra de trabalho

Não começar pela paginação.

A ordem obrigatória é:

1. escrever CTE base
2. provar Cenário B
3. provar Cenário C
4. provar U2
5. adicionar SEM_DADOS
6. adicionar SEM_MONITORAMENTO
7. adicionar COUNT
8. adicionar ORDER BY
9. adicionar LIMIT/OFFSET
10. testar D1/D2

Se B/C/U2 não baterem, não avance.

PARTE A --- CTE BASE POR MONITOR

4. Universo de Monitores

Criar CTE inicial para selecionar:

Unidade
Equipamento
Monitor ICMP

respeitando os filtros existentes:

unidadeId
equipamentoId
monitorId
tipoEquipamentoId

Uma linha lógica por Monitor ICMP.

5. Janelas candidatas

Selecionar janela_monitoramento que intersecta o período:

janela.inicio_em < fimRelatorio
AND
(janela.fim_em IS NULL OR janela.fim_em > inicioRelatorio)

Respeitar semântica:

[inicio,fim)

6. Primeira Medição por janela

Para cada janela:

primeiraMedicao =
MIN(medicao.executado_em)

considerando Medições pertencentes ao Monitor e dentro da própria
janela.

A primeira Medição limita o início observável.

7. Janela efetiva

Calcular:

inicioEfetivo =
GREATEST(
inicioRelatorio,
janela.inicio_em,
primeiraMedicao
)

fimEfetivo =
LEAST(
fimRelatorio,
COALESCE(janela.fim_em, fimRelatorio)
)

Descartar:

inicioEfetivo >= fimEfetivo

Janela sem primeira Medição:

não contribui

PARTE B --- UNIÃO DE JANELAS

8. Normalização

Unir janelas efetivas sobrepostas/contíguas por Monitor.

Pode usar:

window functions
gaps-and-islands
range/multirange

Preferir abordagem clara e testável.

Resultado deve ser um conjunto de intervalos normalizados por Monitor.

9. Tempo monitorado

Calcular:

tempoMonitoradoSegundos =
SUM(EXTRACT(EPOCH FROM (fim - inicio)))

sobre a união das janelas efetivas.

PARTE C --- INCIDENTES

10. Incidentes candidatos

Selecionar Incidentes que intersectam as janelas efetivas.

Incidente fechado:

[iniciadoEm, encerradoEm)

Incidente aberto:

[iniciadoEm, fimRelatorio)

11. Interseção com janelas

Para cada par Incidente × janela normalizada:

inicioIntersecao =
GREATEST(incidente.iniciado_em, janela.inicio)

fimIntersecao =
LEAST(
COALESCE(incidente.encerrado_em, fimRelatorio),
janela.fim
)

Descartar interseções vazias.

12. União de Incidentes

Unir as interseções sobrepostas/contíguas por Monitor.

Não somar simplesmente cada Incidente.

Resultado:

tempoIndisponivelSegundos =
duração da união

13. Contagem de Incidentes

A quantidade de Incidentes é distinta da união temporal.

Contar:

COUNT(DISTINCT incidente.id)

apenas para Incidentes que realmente intersectaram tempo monitorado.

PARTE D --- MÉTRICAS

14. Tempo disponível

tempoDisponivel =
tempoMonitorado - tempoIndisponivel

Garantir:

tempoIndisponivel <= tempoMonitorado

15. Percentual

Se:

tempoMonitorado > 0

então:

ROUND(
tempoDisponivel * 100.0 / tempoMonitorado,
2
)

ou expressão PostgreSQL equivalente que reproduza:

BigDecimal scale 2 HALF_UP

Verificar a semântica de round do PostgreSQL com numeric.

Se necessário, cast explícito para numeric.

PARTE E --- ESTADOS

16. CALCULADO

Monitor com tempo observável:

CALCULADO

17. SEM_DADOS

Monitor ICMP existe, mas não possui janela observável calculável no

18. SEM_MONITORAMENTO

Equipamento sem Monitor ICMP deve ser representado no universo
analítico.

Criar ramo SQL equivalente, por exemplo via:

LEFT JOIN
UNION ALL

ou estratégia segura.

Resultado:

monitorId = null
estado = SEM_MONITORAMENTO
tempos = null
percentual = null
incidentes = 0

Preservar a regra homologada.
