R02.2.2 --- Persistência e Ciclo de Vida do Motor Temporal --- Infra Monitor

1. Objetivo

Concluir a homologação da R02.2 provando que o motor temporal já
validado matematicamente funciona com dados reais persistidos e com o
ciclo administrativo de Monitor e Equipamento.

A R02.2.1 já comprovou o núcleo matemático:

A: 3600 / 0 / 3600 / 100.00

B: 3600 / 1800 / 1800 / 50.00; incidentes=2

C: 10800 / 3600 / 7200 / 66.67

D: 2700 / 0 / 2700 / 100.00

E: 2700 / 300 / 2400 / 88.89

F: 7200 / 1800 / 5400 / 75.00

G: 3600 / 3600 / 0 / 0.00

H: 3600 / 2400 / 1200 / 33.33; incidentes=3

I: 3600 / 0 / 3600 / 100.00

J: SEM_DADOS

K: SEM_DADOS

M: CALCULADO + INFERIDA

N: qualidade INFERIDA

P: percentual null

Portanto, nesta fase o DisponibilidadeTemporalCalculator deve ser
tratado como congelado, salvo se um teste de integração persistida
revelar um defeito concreto.

A fase deve resolver exclusivamente:

homologação da V13 em PostgreSQL;

índice parcial de janela aberta;

backfill legado;

ciclo temporal de Monitor;

ciclo temporal de Equipamento;

rollback transacional;

camada tipada por Equipamento;

SEM_MONITORAMENTO;

regressão completa;

build final.

PARTE B --- BACKFILL LEGADO

9. Cenário legado com Medições

Preparar dados representando estado anterior à V13.

Usar valores fixos.

Exemplo:

monitor.createdAt = 09:00
primeiraMedicao.executadoEm = 09:15
ultimaMedicao.executadoEm = 10:00
intervaloSegundos = 60

Esperado após backfill:

inicio = 09:15
fim = 10:01
origem = INFERIDA

Regra:

inicio =
max(monitor.createdAt, primeiraMedicao.executadoEm)

fim =
ultimaMedicao.executadoEm + intervaloSegundos

10. createdAt posterior à primeira Medição

Criar também cenário em que:

monitor.createdAt > primeiraMedicao.executadoEm

Esperado:

inicio = monitor.createdAt

Isso prova o max().

11. Monitor legado sem Medição

Preparar Monitor sem Medições.

Esperado:

nenhuma janela INFERIDA

12. Janela histórica nunca aberta

Toda janela criada pelo backfill deve possuir:

fim != null

Nenhum legado deve virar janela aberta.

13. updatedAt

Confirmar que updatedAt não participa da inferência.

Não modificar a regra para usar updatedAt.

PARTE C --- CICLO DE VIDA DO MONITOR

14. Clock

Usar:

@Qualifier("monitoringClock")

e Clock controlável nos testes.

Não usar Clock.systemUTC() diretamente no domínio.

15. Criação ativa

Em T0:

criar Monitor ativo

Esperado:

uma janela
inicio=T0
fim=null
origem=PRECISA

16. Criação inativa

Em T0:

criar Monitor inativo

Esperado:

nenhuma janela aberta

17. Desativação

Criar Monitor ativo em T0.

Em T1:

desativar

Esperado:

janela original:
inicio=T0
fim=T1
origem=PRECISA

18. Reativação

Depois da desativação:

em T2:

reativar

Esperado:

janela 1 continua T0–T1
janela 2 inicia T2
janela 2 fim=null
origem=PRECISA

19. Idempotência

Repetir ativação/desativação conforme comportamento permitido pelo
contrato.

Nunca produzir:

duas janelas abertas

20. Histórico imutável

Depois de múltiplos ciclos:

janela 1 fechada
janela 2 fechada
janela 3 aberta

ações atuais não podem alterar os instantes das janelas 1 e 2.

PARTE D --- CICLO DE VIDA DO EQUIPAMENTO

21. Desativação

Equipamento possui:

Monitor A ativo com janela aberta
Monitor B ativo com janela aberta

Em T1:

desativar Equipamento

Esperado:

janela A fecha em T1
janela B fecha em T1

22. Reativação

Antes da reativação:

Monitor A.ativo = true
Monitor B.ativo = false

Em T2:

reativar Equipamento

Esperado:

Monitor A → nova janela PRECISA em T2
Monitor B → nenhuma janela nova

23. Estado administrativo preservado

Reativar/desativar Equipamento não deve artificialmente alterar:

monitor.ativo

Asserção obrigatória.

PARTE E --- TRANSAÇÕES E ROLLBACK

24. Atomicidade

Operações que modificam status administrativo e janela temporal devem
permanecer transacionais.

Criar teste de integração com transação real.

25. Falha forçada

Produzir uma falha controlada durante uma operação que envolva:

alteração administrativa
+
alteração de janela

Depois da exceção/rollback, validar no banco:

status original preservado
janela original preservada
nenhuma janela parcial

Mocks isolados não são suficientes para homologar este requisito.

PARTE F --- CAMADA TIPADA POR EQUIPAMENTO

26. Objetivo

Criar/completar uma camada de aplicação/domínio responsável por produzir
disponibilidade por Equipamento/Monitor a partir dos dados persistidos.

Nome pode seguir a arquitetura existente, por exemplo:

DisponibilidadeEquipamentoService

Não obrigar esse nome se outro for mais coerente.

27. Responsabilidades

A camada deve:

receber Equipamento/período;

identificar Monitores ICMP aplicáveis;

carregar janelas necessárias;

carregar primeira Medição relevante;

carregar Incidentes relevantes;

alimentar o calculador;

produzir resultado tipado.

Controller não deve executar matemática temporal.

29. Múltiplos Monitores --- Cenário O

Equipamento com:

percentuais independentes

média

PARTE H --- CONSULTAS E PERFORMANCE BÁSICA

35. Evitar N+1 óbvio

A integração não deve carregar:

uma Medição por query
um Incidente por query

para cada pequeno intervalo quando isso puder ser evitado.

Não transformar esta fase em otimização ampla.

36. Limite de dados

Buscar somente dados temporalmente relevantes ao cálculo.

Não carregar histórico inteiro de Medições e Incidentes de um Monitor
sem necessidade.
